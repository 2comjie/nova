# Wali

Wali 是一个使用 Go 编写的分布式游戏服务器框架，负责客户端长连接、玩家会话、
请求路由、Node 间 RPC、状态定位、服务发现和应用生命周期，让业务代码专注于聊天、
玩家、房间、匹配和地图等游戏逻辑。

> 项目目前处于基础框架阶段，API 和协议仍可能调整。

## 环境要求

- Go 1.24.3 或更高版本
- Redis（运行完整示例时需要）

## 安装

在你的 Go 项目中按需安装 Wali 包：

```bash
go get github.com/2comjie/wali/packet@latest
```

也可以将 `packet` 替换为需要使用的包，例如：

```bash
go get github.com/2comjie/wali/network@latest
go get github.com/2comjie/wali/app/node@latest
```

## 脚手架

`cmd/wali` 用于创建游戏服务器项目，以及生成 Node、Route、Gate 路由配置和内部
RPC 骨架。

### 安装

在 Wali 源码目录安装当前开发版本：

```bash
go install ./cmd/wali
wali help
```

发布版本可以通过模块安装：

```bash
go install github.com/2comjie/wali/cmd/wali@latest
```

### 创建项目

```bash
wali new github.com/example/game \
  --dir=../game \
  --wali-version=v0.0.0
```

参数说明：

- 第一个参数是新项目的 Go Module 名称。
- `--dir` 指定生成目录，目录必须不存在或为空。
- `--wali-version` 写入新项目 `go.mod`，正式项目应传入已经发布的 Wali 版本。

当前开发版本还没有正式版本号。在本地联调时，可以保留 `v0.0.0`，并把生成项目加入
Wali 的 Workspace：

```bash
go work use ../game
```

### 添加 Node 和 Route

进入生成的项目目录后执行：

```bash
cd ../game

wali add node chat
wali add route chat.send --route=1001 --node=chat --call
wali add route chat.typing --route=1002 --node=chat --tell
```

`--call` 表示客户端需要收到 `Rsp`，`--tell` 表示客户端不等待响应；不传时默认为
`--call`。

脚手架会生成：

- `cmd/gate/main.go`：Gate 启动入口。
- `cmd/<node>/main.go`：Node 启动入口。
- `api/routes.yaml`：Route 源清单。
- `configs/gate/routes_gen.yaml`：Gate 路由配置。
- `internal/gen/route/routes_gen.go`：Route 常量。
- `internal/<node>/routes_gen.go`：Node 路由注册代码。
- `internal/<node>/handler_*.go`：业务 Handler 骨架。
- `api/server/<node>/v1/*.proto`：Node 内部 RPC 协议。

带有 `Code generated by wali. DO NOT EDIT.` 的文件会在后续生成时覆盖；Handler
文件已经存在时不会覆盖。

### 初始化并启动

先确保本机已经安装 `protoc`，然后安装代码生成工具并生成 protobuf：

```bash
make tools
make init
```

启动 Redis：

```bash
docker run --rm --name wali-redis -p 6379:6379 redis:7
```

分别启动 Gate 和 Node：

```bash
make run-gate
```

```bash
go run ./cmd/chat
```

Gate 默认监听客户端地址 `127.0.0.1:8000`，Redis 默认地址为
`127.0.0.1:6379`。可以通过启动参数覆盖：

```bash
go run ./cmd/gate \
  --listen=0.0.0.0:8000 \
  --redis=127.0.0.1:6379 \
  --id=gate-1
```

生成的 `internal/gateway/auth.go` 默认拒绝所有 Bind 请求。客户端接入前必须实现
`Authenticate`，校验 Bind token 并返回 UID。

## 核心模块

- `packet`：网络包格式、字段校验和池化编解码。
- `network`：连接、Session、Bind、心跳、Call、Tell、Push 和生命周期。
- `app/gate`：客户端会话、配置路由、Filter 和 Node 转发。
- `app/node`：业务 Router、Middleware、Handler、Component 和 Gate Push。
- `registry`：服务注册与发现。
- `locator`：玩家 Gate 定位和游戏状态 Node 定位。
- `deploy`：Gate、Node 及其基础设施的组装和启动。

## Packet

客户端协议包含 `Req`、`Rsp`、`Push`、`Ping`、`Pong`、`BindReq` 和
`BindRsp` 七种包类型。固定包头为 20 字节：

```text
+----------+----------+------------+------------+----------------+
| Magic(2) | Type(2)  | Length(4)  | Route(4)   | Seq(8)         |
+----------+----------+------------+------------+----------------+
| Body (Length - 20 bytes)                                      |
+----------------------------------------------------------------+
```

从 `Codec.Read` 得到的消息和 `Codec.Encode` 返回的缓冲区使用内存池管理，调用方在
使用完成后必须调用 `Release`。

## 运行示例

先启动 Redis：

```bash
docker run --rm --name wali-demo-redis -p 6379:6379 redis:7
```

然后参考 [Gate + Chat Node + Player Node 示例](examples/game/README.md) 分别启动
Gate、Chat Node、Player Node 和客户端。

## 开发

运行全部测试：

```bash
go test ./...
```

涉及并发和生命周期的修改还应运行：

```bash
go test -race ./...
```

更完整的领域术语和架构约束见 [CONTEXT.md](CONTEXT.md)。
